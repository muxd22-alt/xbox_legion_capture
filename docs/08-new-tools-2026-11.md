# New this month (November 2026): what applies to a capture feed

Checked 2026-11-22 against GitHub and the lsfg-vk docs. The filter is strict:
it has to run on **Linux + Vulkan + AMD 680M**, work on a **capture feed** (no
game engine), and fit inside the **4x/120** GPU budget.

## Short list

| Project | Created / updated | What it is | Applies here? |
|---|---|---|---|
| **VeyAmux 1.7** | 2026-11-15 / 11-21 | Linux port of Veyra-NRVideo: capture viewer + upscaling + NR + 2x/3x frame gen | **Partly.** Best new picture-quality tool, but caps at 3x (90 fps), not 120 |
| **Passthru** | 2026-11-18 | Flatpak/GStreamer capture viewer, lowest-latency, audio, prefers uncompressed | **As a baseline.** No frame gen |
| **MyGOFrame** | 2026-11-07 | Rust/Swift viewer + recorder, DMA-BUF, colour range, VA-API recording | **For recording only.** No frame gen |
| **ps5-capture** | 2026-11-22 | fish functions: mpv + audio + MangoHud + optional lsfg 2x | **As field notes.** Confirms MangoHud layer-order trap |
| **lyvra** | 2026-11-22 | C++ viewer with FSR 1/NIS/CAS/Anime4K, experimental FSR 3/4, 2x FG | **Watch, don't install.** No release, 0 stars, build-from-source |
| **mpv 0.42.0** | 2026-11-05 | New mpv release | **Mostly no.** `--vf=amf_frc` is D3D11-only (Windows) |
| **lsfg-vk** | last release 2026-09-05 | Frame generation layer | **No November release.** 2.0.0 is current |

Not applicable at all: **EverLive** (AVerMedia PCIe only, your Joyzzz is not
supported), **mpv-AnimeJaNai 3.12.5** (anime models, NVIDIA/DirectML, no AMD
Linux path), **framescale** and **local-upscale** (offline file upscalers, not
live), **FSR 4 / DLSS Enabler game DLLs** (no game to hook).

## VeyAmux — the one worth testing

- Repo: https://github.com/8BiTw0LF/VeyAmux
- Release: `VeyAmux-V.1.7`, AppImage ~86 MB, GPL-3.0 (program AGPL-3.0).
- Explicitly developed and tested on **Bazzite KDE** with an AMD GPU.
- Does capture (V4L2/UVC), audio, upscaling (SGSR, FSR 1, NIS, FSR 3.1.6),
  noise reduction, anti-flicker, FSR 3.1.6 TAA, sharpening, colour, HDR,
  recording/streaming, and a controller-friendly UI.
- It **detects repeated frames** by comparing whole pictures, which is the
  Veyra feature lsfg-vk lacks.
- Frame generation: **Fixed 2x and 3x** through your own lsfg-vk, or free 2x
  with FSR 3.1.6. It writes its own lsfg profile and leaves yours alone.
- Has a built-in 1080p30/60 demo scene and a "Check my setup" report, so you
  can measure the Legion's headroom before touching the Xbox.

### The catch: 30 x 3 = 90, not 120

Its UI exposes 2x and 3x. From a 30 fps game that is 60 or 90; it cannot reach
120. Its duplicate-frame removal makes the input clean, but the multiplier is
still the limit.

So:

- **Keep `mpv` + lsfg 4x as the 120 path.**
- Test VeyAmux as a second front-end if you want better noise handling,
  anti-flicker, or an easier UI. Compare **90 fps with VRR and a cleaner
  picture** against **120 fps with more artifacts**. That is a real preference,
  not a clear win either way.
- Do not expect VeyAmux to replace 4x/120.

## Passthru — useful as a baseline

- Repo: https://github.com/Mikodamas/Passthru
- Flatpak (sandboxed), PyQt6 + GStreamer, AGPL-3.0.
- Always shows the newest frame, drops old ones, plays card audio
  automatically, prefers uncompressed NV12/YUY2, hotplug.
- No upscaling and no frame generation.

Use it to answer "is mpv adding latency?" and to get audio working with zero
setup. It cannot help the 120 goal. It is also the safest thing to install
because the Flatpak sandbox limits what it can touch.

## MyGOFrame — recording, not playback

- Repo: https://github.com/TomoriLab/MyGOFrame
- Rust core, Swift/Go UI, MIT. V4L2 DMA-BUF path, explicit limited/full colour
  range, VA-API recording to AV1/HEVC/H.264.
- No frame gen, no upscaling.

Relevant only if you want to record the Xbox feed on the Legion. The build is
heavy (Swift + Go + Rust) and the AMD encoder path is not hardware-validated by
the author yet.

## ps5-capture — small, but its notes are gold

- Repo: https://github.com/junaydirfan/ps5-capture
- Three fish functions, MIT, 0 stars, created the same day as this check.
- Basically the shell version of this repo: mpv + audio + optional lsfg.

It independently confirms three things that matter:

1. **MangoHud can report 30 fps while frame gen works.** If the overlay loads
   before lsfg-vk, it only sees the app's real frames. lsfg-vk's own docs say
   the same. `docs/02` now warns about this.
2. **`/dev/video0` can swap between boots.** Match the card by
   `/dev/v4l/by-id/...` instead. `docs/02` now uses by-id.
3. **`LSFGVK_*` env vars are ignored unless `LSFGVK_ENV=1`.** Already in the
   official docs, easy to miss.

Its 2x pacing note also matches the math: from 30 fps, 2x only looks even at
60 Hz. 4x at 120 Hz is the clean case.

## lyvra — technically interesting, not ready to trust

- Repo: https://github.com/zeex64/lyvra
- C++20, GPL-3.0, 0 stars, created 2026-11-22, **no releases**.
- Claims: FSR 1 (EASU+RCAS), NIS, CAS (0.02 ms at 1080p->4K), Anime4K,
  experimental FSR 3.1 via optical flow + synthetic jitter + reactive mask, and
  experimental FSR 4 through `fsr4-vk`.
- FSR 3/4 on a capture feed is possible in principle because it estimates motion
  from the video itself, but it is experimental and costs ~3 ms GPU plus ~10 ms
  latency at 1080p. That is a lot next to 4x frame gen on a 680M.
- Frame generation is **2x only**.

Why not now: no binary, 250 vendored FidelityFX shader variants to compile, and
FSR 4 needs AMD's DX12 upscaler DLL extracted and hash-checked. For a 0-star,
same-day repo that is too much trust and effort for no path to 120. Revisit if
it ships releases and gets independent testing.

## mpv 0.42.0 — the interesting part is Windows-only

Released 2026-11-05. Relevant lines:

- `--vf=amf_frc` (AMD Frame Rate Conversion): the manual says **"AMF FRC only
  supports D3D11 input currently"**, so it is a Windows path. Not usable on
  Bazzite.
- Wayland colour management, scRGB, better HDR signalling on DRM: nice, but
  this pipeline is SDR 1080p.
- No new Linux frame generator.

Bazzite will pick up 0.42 when it updates. Nothing to chase manually.

## lsfg-vk — no November release

The newest entry on the official blog is still **2.0.0 (2026-09-05)**. The
GitHub repo is archived and points at `lsfg-vk.dev`. If you see a "new lsfg"
tool this month, it is a wrapper (VeyAmux, Decky plugins, etc.), not a new
layer.

## What actually improves the picture most (free)

Ranked by impact per risk, before any new app:

1. **Capture uncompressed if the card allows it.** YUYV/NV12 at 1080p30 is
   ~124 MB/s, fine for USB 3.0. It removes MJPEG blocking and decode latency,
   which 4x then amplifies. Check with `v4l2-ctl --list-formats-ext`.
2. **Use the by-id device path**, so a metadata node or a reboot cannot move
   your capture.
3. **Deband + CAS in mpv.** Cheap, in-app, no layer conflict. See
   `07-post-processing.md`.
4. **Fix colour range once.** If blacks crush or whites clip, set the Xbox to
   the matching range and/or use mpv's `colorlevels` filter. Do not stack a
   second colour transform.
5. **Do not stack Vulkan layers.** MangoHud, vkBasalt and ReShade-as-a-layer
   all compete with lsfg for the present chain.

## Safety notes for new tools

- An AppImage runs **unsigned and unsandboxed** as your user. VeyAmux publishes
  a `.zsync` and self-updates; verify the release checksum before first run.
  Run it as your user, never with `sudo`.
- A Flatpak (Passthru) is the safer default because of the sandbox.
- A 0-star build-from-source project that vendors AMD DLLs (lyvra) is not
  something to run just to see what happens.
- Anything claiming DLSS/FSR 4 on a plain capture feed without motion vectors
  is either doing optical-flow estimation (experimental, extra latency) or
  exaggerating. There is no free lunch.

## Suggested test plan

Keep the current setup as the control:

1. Baseline: `mpv` + lsfg 4x, 1080p30 capture, 120 Hz. Record smoothness,
   latency and artefacts.
2. VeyAmux: built-in 1080p30 demo first, then the real card. 3x = 90 fps.
   Compare image quality and noise handling against the baseline.
3. Passthru: same card, no frame gen. Compare latency by feel and with a phone
   slow-motion clip.
4. Decide: 120 with more artefacts, or 90 with a cleaner picture. Write it in
   `RESULTS.md`.
